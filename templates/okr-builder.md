# OKR Builder Template

A framework for creating effective Objectives and Key Results.

## OKR Fundamentals

### What Makes a Good Objective
- **Aspirational:** Stretches the team beyond comfortable
- **Qualitative:** Describes a desired future state
- **Time-bound:** Clear deadline (usually quarterly)
- **Actionable:** Team can influence the outcome
- **Aligned:** Connects to company/org OKRs

### What Makes a Good Key Result
- **Measurable:** Specific number or yes/no outcome
- **Ambitious:** 70% completion = success
- **Outcome-focused:** Measures results, not activities
- **Limited:** 2-5 per objective
- **Agreed upon:** Team commits to the measure

## OKR Checklist

### Before Finalizing OKRs

**Objective Quality:**
- [ ] Is it inspiring? Would the team be proud to achieve it?
- [ ] Is it clear? Does everyone interpret it the same way?
- [ ] Is it achievable? Stretch but not impossible?
- [ ] Is it aligned? Does it ladder to org/company OKRs?

**Key Result Quality:**
- [ ] Is it measurable? Can we track it objectively?
- [ ] Is there a baseline? Do we know where we're starting?
- [ ] Is the target ambitious? Would 70% be a good outcome?
- [ ] Is it an outcome? (Not an activity or output)
- [ ] Can we influence it? Is it within our control?

**Overall:**
- [ ] 1-3 objectives maximum
- [ ] 2-5 key results per objective
- [ ] Team understands and commits
- [ ] Check-in cadence defined
- [ ] Grading criteria clear

## OKR Grading

### Scoring Scale

| Score | Meaning | Interpretation |
|-------|---------|----------------|
| 0.0-0.3 | Red | Failed to make progress |
| 0.4-0.6 | Yellow | Made progress, fell short |
| 0.7-0.9 | Green | Strong performance |
| 1.0 | Blue | Exceptional, possibly sandbagged |

### End of Quarter Review

For each Key Result:
1. What was the final result?
2. Score (0.0 - 1.0)
3. What drove the outcome?
4. What would we do differently?

For each Objective:
1. Overall score (average of KRs)
2. Did we achieve the spirit of the objective?
3. Key learnings
4. Carryover for next quarter?

## Common OKR Mistakes

### ❌ Activity-Based Key Results
- "Launch feature X" ← Output, not outcome
- ✅ Better: "Feature X adopted by 500 users with 80% weekly retention"

### ❌ Easy Targets
- "Increase signups from 100 to 105" ← Not ambitious
- ✅ Better: Set targets where 70% achievement = success

### ❌ Uncontrollable KRs
- "Competitor doesn't launch similar feature" ← Can't control
- ✅ Better: Focus on what you can influence

### ❌ Too Many OKRs
- 5 objectives × 5 KRs = 25 things to track ← Too much
- ✅ Better: 2-3 objectives, 3-4 KRs each

### ❌ Set and Forget
- Write OKRs, check at end of quarter ← No course correction
- ✅ Better: Weekly check-ins, adjust tactics, keep goals stable

## OKR Cadence

### Quarterly Rhythm

| Week | Activity |
|------|----------|
| Q-2 | Draft OKRs based on strategy |
| Q-1 | Refine with team, get baseline data |
| Q Start | Finalize and commit |
| Weekly | Check-in on progress, blockers |
| Mid-Q | Deep review, adjust tactics if needed |
| Q End | Score, reflect, learn |

### Weekly Check-in Template
- KR status: 🔴🟡🟢
- Progress since last week
- Confidence level (will we hit it?)
- Blockers/asks
